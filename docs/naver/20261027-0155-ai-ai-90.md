매달 나가는 AI API 비용이나 구독료를 보면 덜컥 겁이 날 때가 있다.

매번 무지성으로 제일 성능 좋은 고급 모델만 선택해서 쓰고 있지는 않은가?

나도 처음엔 일단 제일 좋은 모델을 써야 답도 잘 나오는 줄 알고 무조건 최고 사양만 골라 썼다.

근데 쓰다 보니 통장이 순식간에 녹아내리더라.

사실 우리가 매일 처리하는 업무를 보면 굳이 비싼 모델이 필요 없는 경우가 훨씬 많다.

핵심은 작업의 난이도에 따라서 프롬프트를 효율적으로 분담시키는 거다.

단순한 오탈자 검수나 긴 문서 요약 같은 건 가벼운 하이크나 플래시 같은 가성비 모델한테 맡긴다.

그리고 기획서 논리 분석이나 복잡한 데이터 추론처럼 머리 써야 하는 작업만 고성능 모델로 넘기는 방식이다.

이렇게만 역할 분담을 해줘도 토큰 사용량이 획기적으로 줄어든다.

![비교표](https://jeonnni.github.io/claude-blog-auto/images/20261027-0155-ai-ai-90-compare.png)
`사진 파일: 20261027-0155-ai-ai-90-compare.png`

가벼운 모델과 고성능 모델의 적절한 역할을 비교해보면 차이가 확연하다.

맞춤법 교정, 단순 텍스트 포맷 변환, 한 줄 요약 같은 건 가벼운 가성비 모델이 속도도 훨씬 빠르고 비용은 거의 안 든다.

반면에 전체적인 사업 기획의 논리 검토나 복잡한 코드 작성 같은 건 고성능 모델을 써야 제대로 된 결과를 얻을 수 있다.

모든 작업에 고성능 모델을 쓰는 건 비싼 고급 셰프한테 양파 까기나 마늘 듬듬 썰기를 시키는 거랑 똑같다.

![단계별 가이드](https://jeonnni.github.io/claude-blog-auto/images/20261027-0155-ai-ai-90-steps.png)
`사진 파일: 20261027-0155-ai-ai-90-steps.png`

그럼 실전에서는 어떤 순서로 적용해야 할까?

1단계로 긴 원문 데이터의 1차 다듬기를 가성비 모델로 돌려버린다.

`"아래 원문에서 맞춤법을 교정하고, 불필요한 미사여구를 뺀 뒤 핵심 내용만 3줄로 요약해줘."`

이렇게 정제된 텍스트만 깔끔하게 추출해낸 뒤에.

2단계로 정제된 요약본만 고성능 모델에 넣고 심도 깊은 분석이나 아이디어 구상을 요청하는 거다.

`"위 요약 내용을 바탕으로 이번 프로젝트에서 발생할 수 있는 리스크 3가지와 해결책을 제시해줘."`

처음부터 엄청 긴 원문 전체를 고성능 모델에 넣으면 토큰이 엄청나게 깎인다.

하지만 가성비 모델로 미리 텍스트 크기를 줄여서 넘기면 토큰 지출을 90% 이상 아낄 수 있다.

오늘 알아본 프롬프트 분담법을 요약하면 간단하다.

1. 쉬운 작업과 복잡한 작업을 철저히 구분한다.
2. 1차 다듬기는 가벼운 모델로 빠르게 처리해서 토큰 양을 줄인다.
3. 꼭 필요한 핵심 추론만 고성능 모델에 넘긴다.
